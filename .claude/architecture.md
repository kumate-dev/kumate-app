# Architecture

## Data flow

```
kubeconfig (encrypted, sled + secrets/)
      ↓
ClientRegistry            cached kube::Client per context
      ↓
K8sResources<T> / K8sClusterResources<T> / DynamicK8sResources
      ↓
watch_loop::run           kube-runtime watcher(): bookmark, relist, reconnect
      ↓
ResourceStore             in-memory cache, shard per (event_name, namespace)
      ↓
Tauri event               { type: ADDED|MODIFIED|DELETED|SYNCED, object }
      ↓
frontend store            reduces deltas
      ↓
UI                        virtualized tables
```

The important property: **the apiserver is read once per watch, and every
subsequent UI need is served from memory.** Anything that reintroduces a
request-per-render is a regression.

## Layers and their rules

### `commands/` — the IPC boundary

Thin. A command validates input, delegates, and returns. No business logic. Almost
all of it is generated by the macros in `commands/macros.rs`; only genuinely
irregular kinds (`pods`, `helm`, `custom_resources`, `contexts`, `port_forward`,
`nodes`, `namespaces`, `events`) are hand-written.

### `manager/k8s/` — domain logic

- `client.rs` — `ClientRegistry`: builds and caches clients, gates on connection state
- `resources.rs` — generic CRUD + watch, namespace-scoped
- `cluster_resources.rs` — the same, cluster-scoped
- `dynamic_resources.rs` — the same for runtime-typed CRDs
- `watch_loop.rs` — the single watch driver all three share
- `store.rs` — `ResourceStore`, the in-memory cache
- `pod_resources.rs` — logs and exec (streaming, batched)
- `port_forward.rs` — real kube portforward over a local TCP listener
- `contexts.rs` — kubeconfig discovery, import, credential persistence
- `helm.rs` — Helm CLI wrapper with a Secret/ConfigMap reading fallback

### `utils/` — process-lifetime managers

`WatchManager`, `ExecManager`, `PortForwardManager`, `ConnectionsManager`, `Crypto`.
These own cancellable work and mutable process state.

## State

Two groups, and the split is deliberate — see `state.rs` for the full argument.

**Tauri-managed** (`tauri::State<'_, T>`): `AppState`, `WatchManager`, `ExecManager`,
`PortForwardManager`.

**Process-global** (`T::global()`): `ConnectionsManager`, `ClientRegistry`,
`ResourceStore`. These are read from static functions in the Kubernetes layer that
have no `AppHandle` and are called from ~200 sites. `AppState` exposes accessors for
them so there is still one discoverable entry point.

There is exactly **one** instance of each. `ConnectionsManager` previously existed
both as managed state and as a global; every reader used the global, so the managed
copy was silent dead weight that could drift.

## Extending: adding a resource kind

1. Add the k8s-openapi type import and one macro invocation in `commands/<kind>.rs`.
2. Register the generated command names in `lib.rs`'s `generate_handler!`.
3. Add `src/api/k8s/<kind>.ts` mirroring an existing one.
4. Add the frontend descriptor (columns, status derivation, detail sections).

Steps 1–2 are ~15 lines. If a kind needs more than that, the abstraction is wrong —
fix the abstraction rather than hand-rolling the kind.

## Deliberate omissions

Named here so nobody "fixes" them by accident:

- **No server-side apply.** `update` uses `replace`, which clobbers concurrent
  edits. Switching changes field-ownership semantics for every kind at once, so it
  needs to be one deliberate change with testing, not a drive-by.
- **No list pagination.** `list` fetches everything; `limit`/`continue` are unused.
  Acceptable only because a live watch means `list` is called rarely.
- **Helm watches do not use `watch_loop`.** A Helm release row is a projection over
  storage Secrets, and every revision is a separate Secret collapsing onto one row,
  so `ResourceStore`'s key model does not fit. It keeps a local raw watch and is the
  last place with the terminate-on-stream-end behaviour.
